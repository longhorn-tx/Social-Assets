# Social Assets

A Next.js app for making social media assets (feed posts, Stories, Reels/TikToks,
YouTube thumbnails, LinkedIn visuals, carousel covers) with Higgsfield image and
video models. It's built on the
[Higgsfield Studio template](https://github.com/higgsfield-ai/app-templates)
and ships with the template's full model catalog: 38 picker entries from 28
model files in `generation/catalog/models/`.

## Run it

```sh
cd studio
pnpm install
cp .env.example .env.local   # HF_API_BASE_URL=https://api.higgsfield.ai
pnpm dev                     # http://localhost:3000
```

Click **Connect API key** in the sidebar and paste the API key copied from
[open.higgsfield.ai](https://open.higgsfield.ai/api-keys) as-is. A server action
stores the key in an HTTP-only cookie. Every authenticated Higgsfield request
(submit, status, cancel, signed upload URL) runs on the server with
`Authorization: Key <api-key>`. The browser never receives the key.

## Using it

- **Explore presets** pick a model and the right aspect ratio for each format,
  then fill in a prompt for you to edit.
- **Image / Video** switches surface. The model pill lists every installed model.
  The sliders button opens all of the selected model's settings.
- **+** uploads references. The server gets a signed URL, the browser PUTs the
  file directly to Higgsfield storage, and the public URL is used only after the
  upload succeeds.
- **Generate** turns into **Cancel** while a run is in flight. Cancel calls the
  platform's cancel endpoint; it doesn't just stop polling.
- History and projects are kept in this browser (IndexedDB/localStorage).

## Checks

```sh
pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

## Notes

- `generation/catalog/models.generated.ts` is regenerated by
  `scripts/sync-models.mjs` on every dev/build. Don't edit it by hand.
- Add or refresh models with
  `pnpm dlx shadcn@latest add higgsfield-ai/app-templates/<model>`. List them with
  `pnpm dlx shadcn@latest list higgsfield-ai/app-templates`.
- The key is per user (a cookie in each browser). If you switch to a shared
  server key (`HF_API_KEY`), first add authentication and store each
  `request_id` with its owner. Status and cancel must then check ownership.
